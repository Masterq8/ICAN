# Swin PDF 解析后端比较

日期：2026-09-16。输入：固定 arXiv:2103.14030v2／ICCV2021 PDF，14 个物理页；SHA-256 为 `dfdc7631fe2a35bb5892080b9c0eeadc4432d55cf1856f84bc88802efa877a7c`。

## 选择结果

**P2.1 采用 Docling 主后端＋本项目 adapter；保留 PyMuPDF 的轻量后端与定位恢复能力。** 选择理由是结构化层次、表格候选和原始 provenance 可以继续供分块、证据展示消费，不是速度优势。

复用的是 Docling 文档转换与输出数据类型，新增的工程部分是来源和版本检查、页级适配、代码与配置解析、失败隔离和可重建产物。本节点不引入 PaperQA2 的整套检索／生成流程；它留在问答／Agent 节点作参考基线。

## 比较结果与边界

| 项目 | PyMuPDF 1.28.2 | Docling 2.127.0 主后端 |
|---|---|---|
| 物理页覆盖 | 14/14 | 14/14 |
| 结构化对象 | 文本块与启发式章节候选 | 阅读顺序、章节、文本、公式、表格及 provenance |
| 复杂表格 | 文字和坐标，未恢复可靠单元格关系 | 10 个表格候选；表头归属仍有错误 |
| 双栏问题 | 测试发现合并文本块，已按行 bbox 拆分 | 保留库的阅读顺序；跨页文本另按字符范围适配 |
| 位置恢复 | 原页、原始块坐标 | 原页、同页所有 provenance 坐标；3 个失效跨页范围用原 PDF 坐标恢复 |
| 本机资源观察 | 最终一轮约 0.20秒／69MB 进程 RSS | 缓存后转换约二十余秒／约2.5GB进程 RSS；最终隔离测量见末节 |
| 首次模型准备 | 无模型 | 初次运行约158秒，含下载与初始化，不能当成每篇论文稳态耗时 |

RSS 为采样得到的进程主机内存，不是 GPU 显存。时间包含相应 worker 内的导入与初始化；只测这一篇固定 PDF、没有重复统计分布，不能外推其他格式或吞吐量。

最终串行补测：Docling **22.209秒、2,495.2MB RSS 峰值、14页、74,251字符、238个定位结构、13项警告**。该轮在本任务管线／Swin 冒烟任务结束后执行；不保证其他用户进程或系统负载完全相同。

## 实际检查与修正

1. 对照第7页原 PDF：左右栏各有复杂表格，Docling 表格导出的表头会夹入数值或复合字段。全部表格设置 `review_required`，不把候选结构当作已验证事实。
2. 原 Markdown 格式按最长表头补齐大量空格，使适配文本从约80K进一步膨胀到约130K。已压缩单元格对齐空格与分隔线，保留提取值；不声称这一处理修正了表格结构。
3. 检查原始 Docling 文档发现多个跨页段落。整段放到每一页会制造错误引用，已改为按页 provenance 字符范围切分；同页多个框全部保存，外层框为联合区域。
4. 有些后处理后的跨页字符范围与原文长度不一致。仅在对应原页与 bbox 区域恢复文本，记录 `cross_page_text_recovered_from_pdf`，没有复制另一页文本。
5. 公式项中存在 enriched `text` 为空、`orig` 非空的情况；adapter 保留原始文本，不把空 enriched text 当成公式不存在。
6. 本篇的轻量后端未识别出有效章节候选；Docling 标出 26 个 section_header，包括第5页的 Architecture Variants。该结果只说明本篇文档上的结构覆盖，不能当作普遍准确率。
