## 项目摘要

计算机视觉论文的复现准备并不是简单的“阅读摘要”。研究者需要在论文 PDF、官方代码仓库、配置文件、README 和运行脚本之间反复切换，核对模型结构、训练数据、输入尺寸、评价指标、配置继承和代码前置条件。传统搜索依赖关键词，通用大模型又可能混淆论文版本、模型变体或引用范围，导致答案看似完整，却难以回到原文验证。

**复现有据**是一套面向计算机视觉科研与算法复现的 RAG 与 Agent 工作台。系统将论文、源码和配置转换为带版本、页码、路径及行号的证据单元，通过语义检索、关键词检索、RRF 融合和重排序找到相关材料；再由 Agent 根据问题选择检索、原文读取、配置核查、数值计算和结论提交工具，最终形成带引用、可回查、可修订的研究记录。

产品覆盖论文检索与筛选、自动实验信息卡、论文内证据搜索、历史版本比较、多论文对照报告、Agent 复现核查和只读演示回放。AI 负责理解问题、发现证据、抽取字段和组织回答；确定性程序负责范围限制、结构校验、数值与前置条件检查；研究者负责最终复核。三者共同构成“问题—证据—结论—修订”的完整闭环。

## 一、项目背景

### 1.1 应用背景

Swin Transformer、Vision Mamba、SAM、U-Net 等视觉模型持续演进。研究生和算法工程师在确定课题或启动实验前，通常要完成以下工作：

1. 找到与研究问题相关的论文，并判断是否值得深入阅读。
2. 提取任务、模型、数据集、输入设置、训练策略、指标和实验结果。
3. 找到官方代码、配置文件与运行入口。
4. 判断论文描述与代码默认值是否一致。
5. 区分不同模型尺寸、不同数据集和不同配置分支。
6. 把关键结论整理成可供导师、同学或团队复核的材料。

这类工作频繁、耗时，并且高度依赖来源细节。一个错误的输入尺寸、一条被覆盖的配置或一个混入的模型变体，都可能使后续实验建立在错误条件上。

### 1.2 现有方式的不足

目前常见工具主要解决“搜索论文”“总结 PDF”或“与文档对话”中的一个环节，论文与代码之间缺少统一证据链。用户得到答案后，仍需手工重新查找原文、确认版本和整理记录。对于涉及代码条件、配置继承或跨来源冲突的问题，单轮问答尤其容易遗漏必要证据。

本项目选择计算机视觉论文复现准备作为切入点，不追求一次性覆盖全网论文，而是先在精选、固定版本的语料中把证据定位、Agent 工具调用和人工复核流程做完整，再逐步扩展学科与数据来源。

## 二、痛点分析

| 痛点 | 具体表现 | 造成的影响 |
|---|---|---|
| 资料分散 | 论文、代码、配置和运行说明位于不同页面与文件 | 频繁切换，重复查找，容易遗漏实现细节 |
| 版本与变体混淆 | 同一仓库包含 Tiny、Small、Base 等模型及多套数据配置 | 将其他变体的参数误用于目标模型 |
| 引用难以核查 | 回答只有链接或模糊出处，缺少页码、路径和行号 | 用户无法快速判断引用是否真正支持结论 |
| 配置链复杂 | 默认值、BASE 继承、命令行覆盖和运行时计算分散 | 只看单个 YAML 文件无法还原最终设置 |
| 信息提取重复 | 每篇论文都要重新抄录任务、数据集、训练和指标 | 记录格式不统一，缺项难以及时发现 |
| 横向比较失真 | 不同论文使用的任务、数据集、指标和输入设置不同 | 容易对不可比结果进行直接排名 |
| AI 过程不可见 | 用户只看到最终答案，不知道模型查了什么、为何停止 | 难以判断答案可靠性和失败原因 |
| 研究记录不可追踪 | 人工修订直接覆盖旧内容 | 无法复盘模型建议、人工修改和证据变化 |

## 三、需求分析

### 3.1 目标用户

| 用户群体 | 核心任务 | 主要需求 |
|---|---|---|
| 计算机视觉方向研究生 | 选题调研、论文阅读、课程或毕业课题复现 | 快速筛选论文、整理实验信息、保留引用、形成复现清单 |
| 科研人员与实验室成员 | 组织专题调研、比较方法、复核研究结论 | 统一字段格式、版本追踪、多人可检查的证据记录 |
| 算法工程师 | 评估开源模型、核对参数、准备迁移或复现实验 | 定位代码与配置、识别前置条件、减少试错成本 |
| 指导教师与技术负责人 | 审阅学生或团队的调研结果 | 快速查看结论依据、冲突来源和待确认事项 |

### 3.2 典型使用场景

**场景一：论文快速筛选。** 用户输入“研究 shifted window 的视觉 Transformer”，系统在限定语料中返回相关论文、来源版本、证据摘要和筛选建议。

**场景二：实验信息整理。** 用户选中论文后生成实验信息卡，系统提取模型、数据集、输入设置、训练策略、指标、结果、限制和代码入口，并为每条内容绑定原文。

**场景三：代码条件核查。** 用户询问 PatchMerging 在指定 H、W、L 条件下是否满足源码断言。Agent 检索官方代码，读取原块，调用确定性核查工具，再返回带源码行号的回答。

**场景四：模型对比。** 用户比较 Swin Transformer 与 Vision Mamba 的架构、复杂度、输入处理和实验设置。系统先对齐字段，再显示一致项、差异项和不可直接比较的条件。

**场景五：研究记录复核。** 用户或导师查看历史版本，比较模型初次提取结果与人工修订内容，并回到对应论文页或代码行检查依据。

### 3.3 功能需求

| 编号 | 功能需求 | 完成标准 |
|---|---|---|
| FR-01 | 自然语言检索限定论文与代码语料 | 返回候选、来源类型、版本和可定位证据 |
| FR-02 | 论文筛选与筛选理由记录 | 支持纳入、排除、待定和人工修订 |
| FR-03 | 自动生成结构化实验信息卡 | 覆盖九类核心字段，缺失内容不自动补写 |
| FR-04 | 论文内二次证据搜索 | 搜索范围固定在当前论文，不跨论文误取证 |
| FR-05 | 原文证据回查 | 可查看论文页码、章节、源码路径、代码行和版本 |
| FR-06 | 研究记录历史与差异 | 新结果追加版本，支持任意两版比较 |
| FR-07 | 多论文对照报告 | 对齐字段并提示任务、数据集、指标等不可比条件 |
| FR-08 | Agent 复现核查 | 展示工具轨迹、结论状态、停止原因、用量和引用 |
| FR-09 | 报告导出 | 支持生成和下载 Markdown 研究报告 |
| FR-10 | 离线演示与错误恢复 | 无 API 时可载入固定案例，在线失败不破坏已有结果 |

### 3.4 非功能需求

- **可追溯性：** 关键字段和回答能够回到固定来源位置。
- **稳定性：** 单个模型调用或工具失败时显示明确状态，不自动重复付费请求。
- **安全性：** API 密钥只保存在环境变量或本地配置中；未知仓库代码默认不执行。
- **可维护性：** 语料、提示、模型、索引和评测配置均可版本化。
- **可用性：** 页面支持桌面浏览器和窄屏布局，主要卡片可展开或收缩。
- **可演示性：** 在线真实执行与只读回放采用同一套页面流程，服务异常时仍能完成展示。

## 四、解决方案概述

### 4.1 产品流程

用户从一个研究问题出发，依次完成候选检索、论文筛选、信息提取、证据核查、版本修订、论文比较和报告生成。Agent 核查作为深度入口，用于需要跨论文、源码和配置进行多步判断的问题。

~~~mermaid
flowchart LR
    A[提出研究问题] --> B[混合检索候选]
    B --> C[论文筛选]
    C --> D[生成实验信息卡]
    D --> E[查看原文证据]
    E --> F[人工修订与版本保存]
    F --> G[多论文比较与报告]
    E --> H[Agent复现核查]
    H --> I[工具轨迹与有据回答]
~~~

### 4.2 系统架构

~~~mermaid
flowchart TB
    UI[Vue 3研究工作台] --> API[FastAPI服务]
    API --> DISC[论文发现与筛选服务]
    API --> CARD[实验信息卡服务]
    API --> AGENT[Agent核查服务]
    API --> STORE[追加式研究记录]

    DISC --> RET[混合检索与重排序]
    CARD --> RET
    AGENT --> TOOLS[检索/原块读取/配置核查/计算/结论提交]
    TOOLS --> RET

    PDF[论文PDF] --> PARSE[Docling与来源解析]
    CODE[源码/配置/README] --> PARSE
    PARSE --> CHUNK[结构化分块]
    CHUNK --> DENSE[BGE-M3向量]
    CHUNK --> BM25[BM25词法索引]
    DENSE --> QDRANT[Qdrant]
    QDRANT --> RET
    BM25 --> RET
    RET --> RERANK[bge-reranker-v2-m3]
    RERANK --> EVIDENCE[带位置与版本的Evidence]
    EVIDENCE --> CARD
    EVIDENCE --> AGENT
~~~

### 4.3 数据处理流程

1. **来源固定。** 记录论文版本、官方仓库 commit、文件路径、许可证和来源类型。
2. **结构解析。** 使用 Docling 解析论文结构；源码、Markdown 和 YAML 使用对应解析器保留行号与配置路径。
3. **结构化分块。** 按章节、段落、函数、类和配置块组织文本，保存连续原文范围及定位信息。
4. **建立索引。** BGE-M3 生成语义向量并写入 Qdrant；BM25 建立词法索引。
5. **混合检索。** Dense 召回处理语义问题，BM25 处理类名、配置键和指标名等精确词。
6. **融合重排。** RRF 合并双路候选，bge-reranker-v2-m3 对有限候选再次排序。
7. **生成与核查。** PaperQA2 适配或 Agent 使用检索证据生成结构化结果；程序校验引用范围、字段结构和结论条件。
8. **呈现与保存。** 前端展示字段、轨迹和证据；人工修订以新 revision 保存。

## 五、AI 功能是作品的核心

### 5.1 RAG：让答案建立在指定材料上

本项目中的 RAG 不是附加的聊天入口，而是论文筛选、信息卡、对照报告和 Agent 回答共同使用的证据基础。每个检索结果都携带来源身份，用户可以知道它来自论文、源码、配置还是说明文档，并继续定位到页码或代码行。

Dense 检索擅长理解“层级视觉模型如何降低计算量”等语义问题；BM25 更适合 PatchEmbed、_BASE_、window_size 等精确标识符。两路结果通过 RRF 融合，并由重排序模型选择最相关证据，从而同时兼顾语义理解和技术细节匹配。

### 5.2 Agent：完成多步检索与工具选择

复杂科研问题往往无法通过一次检索解决。Agent 接收问题后，在限定预算和工具白名单内选择下一步操作：

- 搜索论文、代码或配置证据；
- 读取指定证据原块；
- 检查源码中的长度、形状或奇偶性条件；
- 进行有限、可复算的数值计算；
- 提交带证据的结构化 Claim；
- 在证据满足、证据不足、前置条件阻断或预算结束时停止。

网页展示的是工具名称、参数摘要、执行状态和结果摘要，不展示模型私有思维文本。评委能够看到 Agent 如何接收请求、调用工具、获得结果并形成回答。

### 5.3 自动实验信息提取

系统将论文内容整理为统一的实验信息卡，字段包括：

- 任务；
- 模型或方法；
- 数据集；
- 输入设置；
- 训练策略；
- 评价指标；
- 实验结果；
- 局限；
- 代码可用性。

模型负责理解论文语义并提出候选字段，程序负责 Schema 校验、引用存在性检查、同论文范围检查和确定性字段规则。对于没有明确来源的字段，系统保留缺失或进入人工复核，不使用常识自动补写。

### 5.4 Claim 核查与可信状态

系统根据结论类型采用不同策略：

| Claim 类型 | 处理方式 | 典型结果 |
|---|---|---|
| 原文引文 | 检查引文是否位于绑定证据中 | 支持或证据不足 |
| 数值结论 | 使用 Decimal 等确定性计算复核 | 支持、计算冲突 |
| 代码前置条件 | 核对源码断言、输入绑定和允许表达式 | 支持、前置条件阻断 |
| 研究推断 | 检查证据覆盖范围并保留解释边界 | 支持、需要人工复核 |

页面使用“原文匹配”“待人工复核”“证据不足”“前置条件阻断”等状态表达结果。AI 不确定时，产品给用户一个明确的复核入口，而不是生成更自信的措辞。

### 5.5 人机协同与持续修订

用户可以修改筛选结论、字段类型、字段值和引用。每次保存都会建立新版本，旧版本继续保留。系统由此形成“AI 初稿—程序校验—人工复核—版本沉淀”的工作方式，使 AI 提升效率，同时保留研究者对最终结论的控制权。

## 七、作品功能说明

### 7.1 演示中心

演示中心用五个阶段串联整个产品：问题场景、论文筛选、信息卡与历史、Agent 工具、证据与结论。每个阶段可以直接跳转，各功能卡片支持展开和收缩。在线模式显示真实服务状态；只读模式显示固定案例标签。

### 7.2 论文检索与筛选

用户输入自然语言研究问题并选择 Swin Transformer、Vision Mamba 或 QASPER 方法语料。系统返回候选论文、来源版本和证据摘要。用户选择论文后，可查看或修订纳入、排除、待定决定及理由。

### 7.3 自动实验信息卡

点击“从原文生成”后，系统准备当前论文的限定证据，调用模型提交结构化信息卡，再进行程序校验。页面按九类字段展示内容、引用和核查状态。已有记录可以通过“读取已存卡”恢复，避免重复模型调用。

### 7.4 论文内证据搜索与人工修订

对于需要确认的字段，用户可以在当前论文内搜索数据集、指标或结果，选取新的证据，修改字段类型和值并保存。系统不会跨论文取证。修订结果作为新版本保存。

### 7.5 研究记录历史与版本差异

历史面板显示筛选和提取记录。用户可以选择同论文、同类型的任意两个版本进行比较，查看新增、删除、修改和引用变化，区分模型生成与人工修订。

### 7.6 多论文对照报告

用户选择至少两篇已有信息卡的论文后生成对照报告。系统按模型、数据集、输入设置、训练、指标和结果组织内容；当任务、数据集或指标不同，报告明确提示不可直接排名。报告可下载为 Markdown。

### 7.7 Agent 复现核查

用户输入代码条件、研究推断、数值计算或原文引文问题，点击“运行核查”。任务完成后，页面展示：

- 任务状态；
- 规划模型与回答模型；
- 模型调用量；
- 停止原因；
- 工具执行顺序和结果摘要；
- Claim 核查状态；
- 最终回答及引用。

点击引用可在证据面板查看固定仓库版本、文件路径和代码行。

### 7.8 原文证据面板

论文候选、信息卡字段、比较报告和 Agent 回答共享同一证据查看方式。面板展示来源类型、标题、版本、页码或路径、行号和原文摘录，帮助用户快速回查。

### 7.9 双模式演示与错误恢复

完整在线模式连接 FastAPI、索引和模型服务，可执行真实检索与 Agent 任务。只读回放模式载入 Swin 固定案例，不需要 API 或向量数据库，适合作为公网体验和比赛现场备用方案。模型失败、输出截断或预算结束时，页面保留阶段和停止原因，不自动重发请求。

## 八、完整使用说明

### 8.1 运行前准备

完整模式需要已创建的 Conda 环境、恢复后的语料与索引，以及保存在本机环境变量或 .env 文件中的模型服务配置。API 密钥不得写入源代码、提交文档或演示视频。

首次使用前安装前端依赖并构建：

~~~powershell
cd G:\ICAN\frontend
npm install
npm run build
~~~

启动完整后端：

~~~powershell
cd G:\ICAN
conda activate ican
python scripts/serve_api.py --host 127.0.0.1 --port 8000
~~~

浏览器访问：

~~~text
http://127.0.0.1:8000
~~~

开发模式也可以另开终端运行 npm run dev，并访问 Vite 显示的本地地址。

### 8.2 在线完整流程

#### 步骤一：输入研究问题

1. 打开“论文筛选”卡片。
2. 选择目标语料库。
3. 在研究问题输入框填写问题。
4. 点击“检索论文”。

推荐演示问题：

~~~text
梳理 Swin Transformer 的层级架构、Patch Merging、训练数据集、评价指标和主要实验结果，并保留论文原文证据。
~~~

#### 步骤二：选择候选论文

1. 查看候选标题、来源版本和证据摘要。
2. 点击“查看证据”核对命中内容。
3. 勾选需要整理的论文。
4. 若候选不符合目标，调整问题或切换语料后重新检索。

#### 步骤三：生成实验信息卡

1. 点击“从原文生成”。
2. 等待页面显示证据准备、模型提交、结果校验和记录保存状态。
3. 查看筛选决定和九类实验字段。
4. 点击字段旁“查看证据”，在证据面板核对原文。
5. 若已存在信息卡，可点击“读取已存卡”，不会再次调用生成模型。

#### 步骤四：处理待复核字段

1. 在“需要你确认的候选字段”区域输入论文内检索词。
2. 点击“论文内搜索”。
3. 选择更合适的证据。
4. 修改字段类型、字段值或原文引文。
5. 点击“保存为新版本”。

如果模型没有留下候选条目，可使用“手动添加字段”建立人工记录。

#### 步骤五：查看历史差异

1. 展开“记录历史”。
2. 选择筛选记录或信息卡记录。
3. 分别选择两个版本。
4. 查看字段增加、删除、修改及引用变化。

#### 步骤六：生成对照报告

1. 选择至少两篇已有信息卡的论文。
2. 点击“生成对照报告”。
3. 查看字段对照、引用位置和可比性提示。
4. 点击报告中的证据入口复核来源。
5. 下载 Markdown 报告。

#### 步骤七：运行 Agent 核查

1. 展开“复现核查”。
2. 输入核查问题。
3. 选择“代码前置条件”“研究推断”“数值计算”或“原文引文”。
4. 点击“运行核查”。
5. 请求完成后展开真实工具轨迹。
6. 查看任务终态、调用量、停止原因、Claim 状态和最终回答。
7. 点击源码或论文引用完成最后复核。

推荐演示问题：

~~~text
在固定官方 Swin-T 的 PatchMerging.forward 中，给定 H=8、W=8、L=64，长度和奇偶性前置条件是否通过？四路切片拼接后通道维度如何变化？请引用官方源码说明。
~~~

### 8.3 只读回放流程

当 API 未配置或模型服务不可用时：

1. 启动前端开发服务。
2. 打开演示中心。
3. 点击“载入 Swin 只读回放”。
4. 按五阶段导航依次查看论文筛选、信息卡、历史版本、Agent 轨迹和证据。
5. 点击引用，在证据面板查看对应原文。
6. 本地普通模式下可点击“退出演示”返回在线工作台；公网固定演示版保持只读。

回放内容来自固定开发案例，页面会标明“预置演示数据”，不会把它描述为当次模型执行结果。

### 9.2 代表性评测结果

| 指标 | 结果 | 说明 |
|---|---:|---|
| Swin Agent 最终引用必要位置召回 | 81.3% | 最终回答引用覆盖冻结题必要论文页或源码位置 |
| Scoped Dense + QA 必要位置召回 | 50.0% | 固定 Dense 对照工作流 |
| Hybrid/Rerank + QA 必要位置召回 | 56.3% | 混合检索与重排序工作流 |
| Swin Agent 非失败终态 | 8/8 | 每题均返回可检查的任务终态 |

上述指标分别衡量证据位置覆盖、字段证据支持和字段归类，不把单一 Recall 或词面 F1 等同于全部回答正确率。冻结评测数据、配置和结果保持独立，未用于后续调参。

### 9.3 产品质量策略

自动化结果采用分层处理：

1. 通过确定性检查的高置信字段直接展示，并保留证据入口。
2. 存在归类、引文或缺项疑问的内容进入人工复核区。
3. 模型未完成结构化提交时保留失败状态，不保存不完整信息卡。
4. 所有人工修改形成新版本，避免覆盖原始输出。
5. 在线服务异常时使用只读回放保障演示连续性。

## 十、创新性与差异化优势

1. **论文—代码—配置统一证据链。** 不仅回答论文内容，还能关联官方源码、配置路径和版本信息。
2. **混合检索面向科研技术细节。** 语义检索处理自然语言问题，BM25 处理类名、配置键和指标名，重排序进一步筛选证据。
3. **Agent 工具过程可观察。** 页面展示真实工具动作、阶段、用量和停止原因，避免只有黑盒答案。
4. **不同 Claim 使用不同核查方法。** 原文、数值、代码条件和研究推断不共用一种模糊置信分数。
5. **AI 结果可修订、可追踪。** 人工复核与版本差异成为产品流程的一部分。
6. **双模式演示。** 在线模式体现真实 RAG 与 Agent 能力，只读模式保证公网体验和比赛现场稳定性。
7. **面向复现准备的垂直场景。** 相比通用论文总结工具，更关注参数、版本、代码条件、不可比实验和证据闭环。

## 十一、应用价值与发展前景

### 11.1 应用价值

- **提高论文整理效率：** 自动形成统一字段的信息卡，减少重复摘录。
- **降低复现前期风险：** 在训练前暴露版本、输入、配置和评价口径问题。
- **提升研究沟通质量：** 导师和团队成员可以沿引用复核结论，而不是只看摘要。
- **沉淀团队知识资产：** 研究记录、人工修订和版本差异可以持续积累。
- **服务科研教学：** 可用于论文阅读课程、复现作业和 RAG／Agent 工程案例教学。

### 11.2 发展路线

第一阶段继续深耕计算机视觉，扩展 SAM、U-Net、Mamba 等典型模型，并增加遥感、医学影像等垂直语料模板。第二阶段加入用户上传、增量建库、团队空间和协同审核。第三阶段与实验管理系统连接，将论文条件、Git commit、训练配置和实验结果形成完整复现档案。

系统采用统一 Evidence、Claim 和 revision 契约，新领域可以复用解析、检索、核查和前端流程，只需增加领域语料、字段规则与评测集。

## 十三、原创贡献与合规说明

本项目原创工作集中在：

- 论文、源码和配置的统一证据数据结构；
- 带版本与位置的结构化分块和范围约束；
- 适用于科研复现问题的混合检索策略；
- 领域 Agent 工具契约与预算、停止条件；
- 类型化 Claim 核查和前置条件阻断；
- 实验信息卡的确定性规则与人工复核流程；
- 追加式研究记录、任意两版差异和不可比条件提示；
- Agent 安全公开轨迹与双模式演示工作台；
- Swin、Vision Mamba 开发问题及冻结评测体系。

项目复用 PaperQA2、Docling、Qdrant、BGE-M3、bge-reranker-v2-m3 等开源组件，并按各自许可证和固定版本使用。公开论文、代码和数据仅作为研究语料及证据来源；比赛提交前继续核对第三方许可证、署名和再分发条件。API 密钥、模型服务凭证和 Cloudflare Tunnel Token 不进入源码及提交材料。

## 十四、风险控制

| 风险 | 应对措施 |
|---|---|
| 模型生成错误 | 强制引用、字段规则、人工复核、历史版本保留 |
| 相关证据不支持结论 | 类型化 Claim 核查，证据不足时停止或降级 |
| 模型变体混入 | collection、来源类型、版本和安全路径范围过滤 |
| Agent 循环与费用失控 | 工具白名单、调用预算、超时和不自动重试 |
| 外部 API 不稳定 | 已存记录恢复、明确失败状态和只读回放 |
| 未知仓库代码风险 | 默认只做静态读取和条件核查，不执行未知代码 |
| 数据与知识产权风险 | 来源清单、固定版本、许可证核对和必要署名 |

## 结语

复现有据将论文调研从一次性问答转化为一条可核查的研究工作流。RAG 负责把问题连接到论文、源码和配置证据，Agent 负责在有限工具中完成多步核查，确定性程序负责校验结构与条件，研究者负责最终判断与修订。

作品已经形成可运行网页、真实后端流程、固定视觉模型案例、自动实验信息卡、研究记录历史、多论文报告、Agent 轨迹和原文证据回查能力。它既能在比赛中完整展示 AI 接收请求、选择工具、反馈结果的过程，也具备继续扩展为实验室科研知识平台和企业私有研究助手的工程基础。
