# P2.3：Embedding 与持久化索引实施计划

> 沿用用户已确认的task_plan.md和“开始p2.3”授权，按writing-plans／executing-plans在当前任务执行。设计细节属于本节点技术选型，不重新请求已授权工作的确认。

**目标：** 固定模型、revision、实际tokenizer、模板、精度及语料哈希，生成隔离的Qdrant持久化索引；在新进程中核验向量、payload和检索。P2.4 API、PaperQA2接入与正式基准评分继续留在后续节点。

**设计：** BAAI/bge-m3，revision `5617a9f61b028005a4858fdac845db406aefb181`，MIT，Sentence Transformers dense-only、CLS pooling、1024维、8192输入上限。文档直接使用chunk.embedding_text，查询使用原始字符串，无额外指令。GPU float16推理，输出float32归一化向量，Cosine距离。batch_size=8；遇显存问题显式修改配置，不静默改变精度或截断。

**备选及取舍：** multilingual-E5-base更小，但512长度限制可能要求重分块；远程Embedding API依赖密钥和调用预算。首版采用本地BGE-M3，不宣称它已在本项目评测优于其他模型。模型文件仅下载dense所需组件，不下载ONNX／sparse／ColBERT附加权重。

**存储：** 一个本地Qdrant数据库内有三个collection：swin_v1、qasper_train_v1、qasper_validation_v1。运行指纹由配置、模型账本、分块快照和运行库版本共同确定，输出到data/indexes/bge-m3/v1/<完整指纹>；先写独立staging目录，通过验收后原子发布，不覆盖既有成功索引。失败目录保留失败记录，不发布成功manifest。相同输入已有索引时验证再复用。
