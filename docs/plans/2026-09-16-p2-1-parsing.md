# P2.1：Swin 语料解析实施说明

**目标：** 将固定 Swin 论文和官方仓库转换为带来源位置、版本和校验信息的结构化文本，供 P2.2 分块消费。

**授权与设计：** 用户已确认 P2 的流程与节点，并要求按照计划执行。沿用 PDF 按页、代码按文件保留原文和结构位置的设计，本节点在当前任务内完成。

## 设计

### 2026-09-16：用户新增复用调研检查点

当前配置、数据契约与解析器已有初稿，尚未运行管线或验收测试。用户要求先查找可参考项目与数据集，详见 [复用调研](../reference-projects-and-datasets.md)。恢复实现前先在同一 Swin PDF 上比较 PyMuPDF 与 Docling；如采用 Docling，保留结构化 JSON，通过 adapter 接入统一来源／解析单元契约。后端选择待实测，不把初稿解析器视为已经验证。

**检查点完成：** 同篇比较后已采用 Docling 主后端，PyMuPDF 作轻量后端／失效跨页范围定位恢复。新增库版本、模型 commit 和哈希已固定；97个 Swin 单元、20项测试、原文定位检查与重复重建哈希通过。原来的“暂停／待比较”说明保留作变更记录，当前 P2.1 已完成。

- 只读 `data/raw/papers/swin_transformer_2103.14030.pdf` 和固定 commit 的 `data/raw/repositories/Swin-Transformer`。
- 输入配置使用明确来源列表；仓库只枚举 Git 跟踪的文本文件，覆盖 Python、YAML、JSON、Markdown、Shell、TXT 和许可证。
- 主后端复用 Docling 阅读顺序、章节和表格候选，按物理页与 provenance 字符范围适配；失效的跨页范围用原 PDF 对应坐标恢复。轻量后端保留双栏区段排序。表格均标记待核验。
- 代码完整保留文本，使用 Python AST 记录类、函数、嵌套符号和装饰器范围；配置使用安全 YAML 节点解析记录字段路径与行号；Markdown 记录标题区段。
- 每个来源有原始 SHA-256、版本和来源 ID；每个解析单元有稳定 ID、文本 SHA-256、页码或行号，以及字符偏移对应的结构范围。
- 文件读取失败进入失败清单；结构解析失败保留全文并记录警告。版本或原始哈希不匹配时拒绝使用该来源，并返回非零退出码。
- 只写入 `data/processed/swin/v1/`；评测答案和项目需求文档不进入语料。
