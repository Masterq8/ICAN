# P5 演示与历史版本使用说明

## 运行方式

### 不依赖后端的本地演示

```powershell
cd frontend
npm install
npm run dev
```

打开 Vite 显示的本地地址，点击检索栏旁的 **载入演示案例**。这个 Swin 单论文快照随前端一起打包；页面不会请求后端、调用模型、访问本地研究记录或写入浏览器存储。顶部“预置演示数据 · 只读”标识会一直显示。生成、修订、同论文搜证、Agent 和在线检索按钮均停用。

演示包含固定论文与官方仓库版本、12 段论文／配置／代码证据，以及筛选和提取记录各两个版本。最新信息卡覆盖任务、模型、数据集、输入设置、训练、指标、结果、限制和代码入口九类字段，共 14 个条目；每个条目均可打开对应页码或源码行号。历史差异会展示新增、修改和同名多结果，并把论文 Table 1(a) 的 81.3% 与官方仓库 checkpoint 表的 81.2% 按来源分别保留。单篇报告和 Agent 回放使用同一固定来源范围，展示结构化整理、多步检索、工具选择、引用回答及证据不足结论。记录是为演示整理的预置数据，不是本次模型输出、评测 gold 或跨论文比较。退出演示会还原进入前的查询、选择、卡片、报告、证据和编辑内容。

### 在线工作台

项目根目录执行：

```powershell
conda activate ican
python scripts/serve_api.py --host 127.0.0.1 --port 8000
```

前端可用 `npm run dev` 并通过 `/v1` 代理访问 API；也可先运行 `npm run build`，再由 FastAPI 托管 `frontend/dist`。冷启动不探测 `/health`，状态显示“未检测”；第一次检索或读取历史之后才更新连接状态。

## 查看历史和任意两版差异

选择在线候选论文后，页面读取 `GET /v1/research/history/{source_id}` 并分别列出筛选、提取历史。版本按时间从新到旧排序，显示记录ID和`revision_of`。若单个记录文件损坏，其他记录继续显示，并给出不含正文的诊断代码。

在“记录类型”中选筛选或提取，再从两个版本下拉框任意选一对。比较限定同一论文、同一记录类型；差异由前端确定性计算，不调用模型。字段按规范化后的同值优先配对，剩余同名字段依出现顺序配对；需要人工确认的配对会明确标出。表格保留原记录中的值、Claim状态、引文与证据位置。记录契约没有可靠的创建者信息，因此界面不猜测版本由模型还是人工创建。

## 阶段、用量与恢复

自动研究卡返回完成／复核状态、证据准备、模型提交、结果校验与记录保存四个阶段，以及调用量、输入／输出 token 和停止原因。同步请求只在返回后展示实际发生的阶段，不显示虚构实时进度。实际费用未由服务提供时显示“实际费用未提供”。Agent 继续展示服务端实际返回的工作阶段和停止原因。

- 找不到候选时可以修改检索词或载入本地演示。
- 读取历史失败可重试只读请求；它不会重新生成研究卡。
- 生成失败不会自动重发付费请求；错误栏提供只读演示入口。
- 修订请求结果不明时先刷新历史，再决定是否新建版本，避免重复提交。

## 当前边界

本地演示解决无 API、无密钥或服务异常时的展示问题，不能用于验证在线检索或生成质量。P4.6 自动工具成功率门槛仍未通过；字段仍需人工查证。[Vision Mamba 专项问题集和比较卡](vision-mamba-swin-comparison.md)已交付，仍与检索集合及 P6 冻结题隔离。历史记录请求只在确认当前论文和请求编号仍有效后更新页面；演示退出后恢复原历史和所选版本。差异表把研究陈述与原文引文分开显示，同名多条目均提示人工确认。
