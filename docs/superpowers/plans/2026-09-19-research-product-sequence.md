# P4.5→P4.6→P5 执行计划

用户已明确确认顺序：先验证真实提交，再交付自动科研链路，最后做网页；不反复重跑同一开发题，不扩大全量评测代替产品。

## 1. P4.5 协议与真实流程

- [ ] 以本地MockTransport断言OpenAI SDK发出的`tool_choice`和工具schema。
- [ ] 独立一次中性真实协议样例，记录manifest、单次journal和服务端实际工具选择；不含论文题。
- [ ] 新目录、独立预算、固定新科研问题，完整绑定代码／配置／语料版本；一次运行，不重试旧题。
- [ ] 人工检查结论、核查状态、来源和生成回答，记录通过或失败；仅据实际结果更新P4.5。

## 2. P4.6 自动科研流程

- [ ] 从精选论文范围与用户条件生成筛选候选、理由和可修订决定。
- [ ] 自动抽取模型、数据集、训练、指标、结果、限制与代码入口，形成证据绑定的实验信息卡。
- [ ] 对多篇卡片按同口径比较，保留不可比条件与缺口，生成可审阅报告。
- [ ] 复用ResearchService的Claim核查、revision与报告契约；新增必要接口和针对性测试。

## 3. P5 网页

- [ ] Vue页面完成条件输入、候选筛选、实验卡、对照报告和证据跳转。
- [ ] 展示任务状态、费用与失败原因；报告可导出；真实端到端演示。

## 完成口径

旧p4-v3与冻结题只作身份哈希，不读内容、不重跑。代码测试通过不等于真实模型质量通过。每个节点需更新task_plan.md、progress.md、findings.md和问题日志，并保留可复现交付物。
