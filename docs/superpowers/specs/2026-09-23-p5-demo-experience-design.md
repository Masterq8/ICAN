# P5 演示体验设计

## 状态

- 用户已确认设计：2026-09-23。
- 本文定义 P5 第三优先级：历史版本、任务状态、错误与空状态、一键演示和无 API 本地演示。
- 执行顺序以`task_plan.md`为准：完成本节点后，进入 Vision Mamba 专项问题与比较，再进入 P6 冻结评测。

## 背景与目标

当前 Vue/FastAPI 工作台已支持检索论文、创建与恢复研究卡、人工追加修订、Agent 阶段信息和证据查看。研究记录以追加式 JSON 文件保存，记录包含`record_type`、`subject_source_id`、`revision_of`、`created_at`、字段核查状态和证据；服务端目前只查询最新记录，网页没有历史版本列表或差异视图。

本节点要使评审或面试演示者可以：

1. 查看同一论文的历史筛选／提取记录，并任意选择两版查看变化；
2. 不依赖后端或模型 API，一键载入可说明来源和边界的固定 Swin 案例；
3. 运行在线功能时看懂任务状态、实际阶段、模型用量和结束原因；
4. 遇到服务／模型错误或无结果时知道下一步，并避免误触发付费重试。

## 用户体验

### 历史版本与差异

- 当前选中论文的筛选记录和提取记录分别列出，按`created_at`从新到旧显示记录时间、记录类型及`revision_of`链接。当前记录契约不保存可靠的作者类型，界面不推断记录来自模型还是人工。
- 用户可在同一类型中选择任意两版；默认将最新两版作为初始选择。筛选与提取记录不能互相比较。
- 提取差异按字段名展示新增、删除、修改、未变化四类；每格保留值、Claim状态、引文和证据位置。筛选差异展示decision和理由Claim的相同信息。
- 字段多重集先按规范化后的完全相同字段配对，再把剩余的同名字段按原出现顺序配对。若同名条目无法无歧义对应，界面标注“按出现顺序匹配，需人工确认”；不得隐藏重复项，也不得据此重排字段。
- 只读浏览历史，不提供覆盖或删除历史记录。修订仍按现有`revision_of`追加接口写入。

### 一键与离线演示

- 在检索操作旁提供“载入演示案例”按钮，使入口无需先输入查询或等待 API 健康检查。
- 本节点固定案例为单篇 Swin 论文；由随前端发布的只读 fixture 提供查询、候选论文、原文证据、筛选与提取记录、历史修订和单论文研究报告。
- 固定案例只用可回溯到当前 Swin 论文版本的真实证据。fixture 中的人工整理结果标注为“预置演示数据”，不声称来自本次模型调用、不作为评测gold，也不代表自动抽取质量。
- 演示模式不调用任何后端或模型 API，不访问ResearchStore，不产生写操作。所有新增、修订、运行 Agent 等写／生成操作在演示模式禁用或明确说明只读。
- 单篇案例的报告使用预置单论文报告快照；不得把它显示成多论文比较或性能排名。
- 页面启动时不自动请求`/health`；连接状态先显示“未检测”。用户主动执行在线检索／生成时才访问API。网络或模型请求失败时保留当前查询、选择和已显示内容，给出明确错误与“载入演示案例”动作。错误恢复不自动重发已开始的付费请求。
- 退出演示时清空演示状态并恢复在线工作台；不清除用户已存在的在线研究记录或未提交输入。

### 任务状态、阶段、用量与停止原因

- Agent继续显示后端返回的真实`workflow_stages`、`status`、`stop_reason`和`paid_calls`，不重新推断或翻译成成功状态。
- 自动研究卡响应增加有界、可枚举的执行阶段摘要，至少区分证据准备、模型提交、结果校验、记录保存；各阶段的状态来自实际控制流，错误有相应失败阶段和停止原因。
- 当前请求是同步请求，不引入WebSocket、后台任务或虚假的逐步实时进度。运行中显示“正在检索／生成／保存”等当前操作提示；响应结束后展示真实阶段摘要和调用量、输入／输出token数。用量缺失显示“服务未提供”，不估算实际费用。
- 成功、需要人工复核、无工具提交、证据不足、超时、预算耗尽、服务不可用分别给出可理解状态与相应下一步。不得因UI恢复而自动重复付费调用。

### 错误、加载和空状态

- 区分服务离线、检索无候选、当前论文无历史卡、无可比较版本、生成失败、模型无提交、证据不足和历史读取失败。
- 每个状态说明当前事实，并提供适合动作：修改查询、查看已存记录、同论文内搜证、载入只读案例或重试纯本地读取。
- 保存失败时保留编辑表单及用户输入；明确说明是否已提交，避免用户因不确定而重复发起付费操作。
- 所有只读演示数据和在线数据使用明显不同的状态标识。

## 实现边界与数据流

1. `ResearchStore`增加按论文读取全部记录的只读操作；不扫描非记录文件作为记录，不改变现有append-only行为。单个记录文件损坏时保留其他可读记录，并返回不含敏感正文的错误诊断。
2. FastAPI新增论文历史读取接口，返回筛选／提取分组、时间排序的`ResearchRecord`及无效记录诊断；证据位置从已有Evidence契约读取，不复制来源元数据。
3. 前端历史面板消费接口响应，本地对所选两版做确定性差异计算；不调用语言模型进行差异总结。
4. 离线fixture作为静态前端资产随构建交付，在线API不可用时也可以载入；离线分支不调用`fetch`、后端、模型或持久化存储。
5. 自动卡阶段摘要从`ResearchAutoService`实际步骤构造。错误响应中的停止原因不包含API密钥、完整环境变量或不必要的内部堆栈。

## 验收标准

- 任意同论文、同类型两版可比较；跨论文或跨记录类型请求被拒绝或不能在UI选择。
- 历史列表包含全部有效版本并按时间稳定排序；孤立、损坏记录不会使其他有效记录整体不可读，且错误可诊断。
- 差异保留重复字段；相同项、增删改和歧义同名项按本文规则显示；证据状态及位置与原记录一致。
- 页面冷启动不自动请求API；一键案例从空页面或API离线状态都可载入，包含真实来源标识、证据位置、研究卡和单论文报告；演示加载、浏览和退出全流程零API请求、零模型调用、零记录写入。
- 在线和演示数据标识始终可见且不能混淆；退出演示恢复在线状态。
- Agent真实阶段保持原样可见；自动卡阶段只反映确实发生的操作；所有停止状态展示调用／token数据和明确原因（服务未提供时标缺失）。
- 关键错误不丢用户输入，不自动重试模型请求；错误页面至少有一个安全、可执行的后续动作。
- Vue production构建通过；历史API／diff／离线模式和状态映射有针对性自动化覆盖；使用浏览器走查在线与离线主流程。

## 明确不做

- 不修改P4.6封存、人工审核或质量门结果，不重复模型评测。
- 不在本节点制作Vision Mamba专项问题集或参数／FLOPs对比，不运行P6冻结评测。
- 不引入新的在线服务、数据库或后台任务基础设施；保留现有本地文件记录和同步HTTP流程。
- 不让演示数据写入用户研究记录，不把演示记录、预置报告或示例调用量计为真实模型结果。

## 方案选择记录

采用扩展现有Vue/FastAPI工作台的方案：历史查看共用现有记录契约，一键案例共用显示组件但从本地fixture读取。未选择独立演示页面（会重复实现和分叉）或模拟后端（仍依赖服务并更容易混淆预置结果与实时结果）。

用户选择的界面方向：版本比较使用“任意两版 + 变更表格”；演示按钮放在检索操作旁；第一个固定案例为单篇Swin论文；API离线时载入固定只读案例。
