# 演示中心与 Agent 过程展示设计

## 状态

- **状态：待用户审阅。** 本文是设计方案，不代表功能已经实现。
- 用户已确认：采用 C 方案，在现有工作台旁增加“演示中心”；使用真实同步执行、结束后展开真实轨迹；提供离线回放和在线真实执行；先用一篇 Swin 论文串联流程。
- 方案须与既有 P5 设计及其只读、无 API 演示约束保持一致。既有细节见 [P5 演示体验设计](2026-09-23-p5-demo-experience-design.md)和[当前开发计划](../../../task_plan.md)。

## 问题与目标

比赛视频要求观众能看清作品如何接收请求、调用智能体、协同其他模块、返回有依据的结果，并理解真实应用价值。当前工作台已有论文检索、筛选／提取卡、证据查看、历史版本和 Swin 离线快照；但尚缺一个按演示叙事组织的入口，Agent 的工具轨迹也没有作为清晰的可审计过程展示。若直接录制零散页面，评审难以在五分钟内理解各模块关系；若用假的逐步动画，又会把同步请求包装成并不存在的实时决策。

本方案要在网页里提供一条完整且可录制的展示路径：**提出科研问题 → 找到并筛选论文 → 提取研究信息 → Agent 选择并调用工具 → 查看证据与逐条结论 → 阅读研究输出及边界**。演示同时适用于比赛评审和求职作品集，能说明开发者实际实现过 RAG、工具调用、证据绑定、失败处理和全栈协作。

## 目标用户和场景

- 主要用户：大赛评审、面试官，以及第一次使用 ICAN 的研究者。
- 核心演示：围绕一篇固定版本的 Swin Transformer 论文，核查论文、代码与配置之间的一个可由现有语料支持的问题。
- 主要观看场景：桌面浏览器现场演示、5 分钟录屏；窄屏可浏览但不作为录制主布局。
- 演示问题、证据和 Agent 轨迹必须来自一个真实、可重复说明来源的开发样例。不得选用 P6 冻结题、冻结答案或其输出作为交互演示 fixture。

## 方案选择与页面结构

采用用户选择的 **C 方案：新增“演示中心”入口，同时保留现有科研工作台**。演示中心负责讲清功能如何协作；工作台继续承担自由检索、生成、修订与研究操作。两个入口共用既有组件和 API，不复制一套产品逻辑。

演示中心采用横向阶段导航和纵向内容区。阶段导航可跳转，但每一步都保留在单篇 Swin 案例中的上下文：

1. **问题与场景**：展示研究者要确认的具体问题、相关痛点及本次运行模式。
2. **论文发现与筛选**：展示检索问题、候选来源、纳入／排除／待核查结论和筛选证据。
3. **信息卡与版本**：展示研究设计、模型结构、输入处理、实验设置等提取字段，附 claim 状态、证据位置和历史版本变化。
4. **Agent 执行轨迹**：展示请求完成后的实际工具调用顺序、工具结果及下一步研究产物。
5. **证据与研究结论**：打开原文 PDF 页或代码行，查看逐条结论状态、引用、报告摘要和适用边界。

演示中心顶部始终显示当前模式：

- **预置运行回放 · 只读**：本地快照中的结果与轨迹；不发起在线执行。
- **在线真实执行**：只在用户明确点击“运行 Agent”后提交；由服务端返回完成结果和轨迹。

不得仅用颜色区分模式；使用文字标签和不同的模式说明。在线或离线切换不得丢弃已有工作台输入；退出演示后返回原工作台状态。

## Agent 过程展示

### 在线真实执行

后端当前以同步 HTTP 请求完成 Agent 任务，响应包含 `status`、`stop_reason`、`workflow_stages`、`trajectory`、答案和用量。页面在请求期间只展示实际请求状态（例如“正在执行，等待服务端返回”），不自行播放预计阶段、不伪造工具步骤或百分比。请求完成后，将响应映射为按发生顺序排列的轨迹，并显示真实终态。服务端未提供的数据明确标为“未提供”。

轨迹分为三个可理解的区块：

1. **任务目标**：展示用户提交的问题和选定论文／语料范围。
2. **工具协作**：逐项显示真实调用的工具名称、经白名单处理的参数摘要、执行成功／失败／命中缓存状态、有限长度的结果摘要。失败工具仍保留在轨迹中，并说明系统如何停止或继续。
3. **结论与证据**：显示实际答案、引用和 claim 核查状态；证据链接打开已有证据面板，定位到原文页码、代码行或段落。

轨迹视图不得显示模型的隐藏思维链、planner 原始文本、完整内部消息、密钥、环境变量、无关大段工具原始输出。工具参数按类型白名单裁剪；结果摘要只做确定性截取和错误状态映射，不让另一轮模型臆造过程解释。若某个工具没有可显示的安全参数或结果摘要，显示工具名及实际状态即可。

前端目前的 `AgentResponse` 类型尚未包含 `trajectory`，现有页面主要呈现状态、阶段、回答与产物。实现时需要补齐前端响应类型和安全展示模型；服务端应提供或映射有界的公开轨迹字段，不把原始 planner action 原样展示给用户。没有轨迹时保留阶段、终态和回答，并如实提示“本次服务未返回详细轨迹”，不补造事件。

### 离线预置回放

- 复用现有 Swin 只读案例的论文、证据、筛选、信息卡、历史版本和报告快照。
- 增加一份来自**真实开发样例运行**的 Agent 轨迹快照。应记录其问题、论文／源码版本、模型与运行时间、实际工具调用和终态；只保留网页展示所需的安全白名单字段。
- 预置回答及轨迹始终标记为“预置演示数据”，不会被描述为当前实时调用，也不计入 P6 或质量评测。
- 加载、逐页浏览和退出 fixture 全程不访问 API、不调用模型、不写 ResearchStore 或浏览器持久化存储。Agent 执行按钮在回放模式禁用，并说明可以切换到在线模式发起真实任务。
- Cloudflare Pages 静态演示构建通过 `VITE_DEMO_ONLY=true` 固定进入只读回放：页面加载时自动载入 Swin fixture，隐藏退出回放与在线 Agent 入口，禁用在线检索和写入操作；默认本地构建保持原有在线／回放切换能力。
- 如果开发样例没有可验证的真实轨迹，则本地回放明确显示“该样例暂不含 Agent 轨迹”，不可用手工编排的假调用补齐。

## 五分钟展示脚本

时间用于录屏编排，不作为产品性能承诺。在线请求可能超出分配时长；现场和录屏主路径应优先使用已核验的只读回放，在线执行作为真实交互补充。

| 时间 | 网页操作与讲解 | 要证明的能力 |
|---|---|---|
| 0:00–0:30 | 打开演示中心，说明“论文结论、代码实现和配置约束分散，研究者需要逐条确认来源”以及单篇 Swin 场景 | 问题真实、目标明确、演示边界清楚 |
| 0:30–1:05 | 展示检索请求、候选论文及筛选 decision，指出纳入／排除所依据的原文证据 | RAG 检索与筛选如何协作 |
| 1:05–1:45 | 展开实验信息卡与一个版本差异，指出字段、claim 状态和原文位置 | 结构化信息提取、历史可追溯 |
| 1:45–3:10 | 说明离线回放或点击在线运行；请求等待时不编造进度，完成后沿真实轨迹查看工具选择、调用结果和终态 | Agent 接收任务、调用工具、处理结果 |
| 3:10–4:20 | 点击引用定位到论文页／代码行，查看支持、待复核、证据不足或前置条件阻断等结论 | 逐条证据核查与失败诚实呈现 |
| 4:20–5:00 | 打开研究输出、历史与边界说明，概括用户能复核什么、系统不能确认什么 | 场景价值、可审计性和可信边界 |

脚本中的结论和价值判断须由当前 fixture 的证据支持。不得声称未测量的效率提升、准确率或商业收益；可强调可复核证据、调用过程透明、错误不自动重试、无 API 时仍可展示产品流程等可观察优势。

## 交互状态与失败恢复

- **运行中**：保留用户问题和所选论文，显示同步请求正在等待，不显示虚构的阶段完成比例；防止同一任务因重复点击而并发提交。
- **成功或有答案**：显示真实工具轨迹、回答、引用、用量（若 API 返回）和结束原因。
- **证据不足／需要复核／前置条件阻断**：明确说明结论边界，允许打开已有证据或回到问题调整；不以绿色成功样式掩盖限制。
- **预算耗尽／超时／服务错误**：显示真实终态和可执行下一步；不自动重跑可能付费的请求；保留错误前的页面内容。
- **工具失败或无轨迹**：保留实际发生的步骤和停止原因；区分“没有调用”“调用失败”和“服务没有提供详情”。
- **在线历史读取失败**：保留当前选择，允许纯读取重试或切换到有明确标识的离线回放。

## 实施边界

### 纳入范围

1. 在现有 Vue/FastAPI 产品中增加演示中心入口和五阶段引导布局，复用现有筛选、信息卡、历史差异、证据面板与研究报告组件。
2. 为 Agent 响应补齐轨迹类型、安全公开投影与可访问的时间线展示；以服务端真实事件为准。
3. 为现有 Swin 离线 fixture 配置独立开发样例的可核验轨迹快照和来源元数据。
4. 区分只读回放与在线真实执行；保持同步请求，不增加 SSE、WebSocket 或后台任务基础设施。
5. 补充忙碌、证据不足、待复核、停止、错误和轨迹缺失等状态呈现及桌面浏览器走查。

### 不在本轮范围

- 不重做 P5 已完成的历史差异、离线演示和错误恢复机制；仅在新演示叙事中复用、缺漏时适配。
- 不增加假实时流、模拟在线调用、隐藏思维链、模型自动解释轨迹或自动重试。
- 不改 Agent 规划策略、检索算法、生成提示、P6 冻结集、冻结结果或已封存质量门。
- 不增加新的模型服务、计费机制、帐号系统或在线部署；不承诺在线公网可访问。
- 不生成比赛视频文件或 20 页以内的正式应用方案；本节点交付网页展示方案和可照着录制的脚本，视频制作另行安排。

## 验收标准

1. 新用户无需先读开发文档，即可从“演示中心”按阶段走完单篇 Swin 案例；现有工作台仍可独立进入和操作。
2. 页面明确区分只读回放和在线执行；回放加载、浏览、展开轨迹及退出全程零 API 请求、零模型调用和零持久化写入。
3. 回放轨迹能追溯到独立开发样例的真实运行记录；问题、来源版本、工具顺序和终态与原记录一致，不引用 P6 冻结题或答案。
4. 在线执行只有用户明确点击后才提交；运行等待过程不伪造进度；结束后轨迹只呈现服务端实际返回的公开字段。
5. 轨迹不暴露 planner 原始 action、模型隐藏推理、API 密钥或无关原始结果；缺少字段时使用“未提供”或省略，不推测。
6. 轨迹的工具事件、状态、结果摘要与回答／证据一致；点击证据可以回到现有 PDF 页、代码行或段落位置。
7. 对成功、证据不足、需人工复核、前置条件阻断、工具失败、预算耗尽、超时、服务异常和无详细轨迹均有明确展示；错误恢复不自动重新提交付费任务。
8. 16:9 桌面浏览器按脚本走查可在五分钟内完成主要内容；阶段跳转和键盘焦点可用，窄视口布局不遮挡关键状态。
9. 验收只使用开发样例和交互检查，不运行 P6 冻结题、不用冻结结果调参、不重复付费调用同一旧题来改善展示。

## 计划交付物与可调整节点

后续实现计划应拆成独立、可回滚的交付节点；新发现的问题或点子记录进开发计划后再决定是否影响当前范围：

| 节点 | 交付物 | 验收重点 |
|---|---|---|
| D1 演示中心骨架 | 导航入口、阶段结构、模式标签、单篇 Swin 上下文 | 保留现有工作台；布局和状态符合本设计 |
| D2 安全轨迹契约 | 后端有界公开轨迹映射、前端类型与状态映射 | 只呈现真实白名单事件；无私有推理／敏感数据 |
| D3 Swin 回放样例 | 独立开发题的核验轨迹快照与来源说明 | 对照原始真实响应和证据；离线零网络、只读 |
| D4 在线状态与异常路径 | 同步执行等待态、结束轨迹、失败及边界呈现 | 明确点击才执行；不假进度、不自动重试 |
| D5 录制验收 | 五分钟脚本浏览器走查、截图／录制检查清单 | 页面可读、证据可跳转、步骤连贯、视频讲述完整 |

节点顺序可根据开发过程中发现的接口缺口调整，但若要改变离线回放边界、在线请求方式、展示的轨迹数据或冻结评测隔离，需先更新本设计并由用户确认。
