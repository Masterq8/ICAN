# P4.6 v2 新样本质量门与可核查降级设计

## 目标

在已经支持同类字段多条目的协议上，使用 8 篇从未进入任何历史运行产物的 QASPER train 论文，完成一次独立、不可重试的 `deepseek-v4-pro` 真实质量验收。验收同时衡量工具协议稳定性和字段语义质量。

若质量门未通过，产品进入“高置信结果 + 待核查候选”模式：系统继续给出最可能的结果，但不把不可靠候选伪装成确定事实，用户可直接查看、搜索原文并确认或修订。

## 冻结样本与运行规则

- 固定 8 篇新的 QASPER train 论文，按 `source_id` 与历史 evaluation、research、replay 产物做全集排除。
- 每篇固定统一研究问题、论文版本、索引指纹以及 6 条实际模型输入证据。
- 每篇只允许一次 `deepseek-v4-pro` 调用；调用前写 started marker，失败后不重试、不换题。
- 使用独立配置、运行目录、记录库、journal、trace 和 8 次硬预算。
- 原始动作、usage、诊断和成功卡片全部原样保存；人工或 AI 审核不得改写模型输出。
- 本次使用当前多条目协议。同名字段允许重复，每条保留独立的值、引文和证据 ID。

## 预先固定的质量门

只有以下条件同时满足，P4.6 v2 才可判为通过：

1. 工具提交成功率不少于 7/8。
2. 全部可解析原始字段的原文支持率不少于 90%。
3. 全部可解析原始字段的归类正确率不少于 85%。
4. 缺失字段识别率不少于 85%。
5. 不出现越界证据、无 trace 的付费调用或无法解释的服务端错误。

字段指标基于所有可解析原始草稿，不能只统计成功卡片。工具协议失败仍进入提交成功率分母。已有字段槽位覆盖率、每类混淆和遗漏字段作为诊断指标，不作为单独通过线。

## 审核方法

审核单位是字段 occurrence，而不是去重后的字段名。每条字段分别判断：

- 引文是否来自它指定的证据片段；
- 引文及上下文是否支持字段值；
- 字段类型是否正确；
- 若错误，最合适的类型是什么；
- 九类字段中哪些在六条输入证据内确实存在；
- 已存在但模型遗漏了哪些字段。

确定性规则继续对 dataset、metric、result 的强冲突给出提示，但不自动改写标签。审核结果明确记录审核者身份：Codex／模型辅助属于 AI 审核，不能写成已完成人类审核。完整工作表供用户最终确认。

## 错误诊断

每个失败必须落到稳定诊断码和具体字段路径，包括无工具调用、多工具调用、JSON 错误、schema 错误、证据越界、字段语义冲突或运行时异常。报告同时展示原始字段数量、重复类型、遗漏字段和引用问题，不以 `ToolInputError` 作为最终原因。

## 未通过时的产品降级

若任一质量门未满足，自动卡接口仍返回可核查结果，但分为两组：

- **高置信字段：** 工具结构合法、引用连续存在、确定性规则未发现冲突。界面正常展示字段值、原文和位置，但继续注明“原文匹配不等于研究解释已确认”。
- **待核查候选：** 工具结构不完整、引用不支持、类型冲突、存在多个合理类型，或重要字段未提取。界面展示最可能字段类型、候选原文、来源位置和诊断原因。

用户可从候选项执行以下操作：

1. 打开当前候选证据。
2. 在当前论文的限定语料内按关键词搜索更多证据，不开放到其他论文。
3. 选择正确类型、编辑值、选择一条或多条证据。
4. 确认为新的 extraction revision，保留自动生成版本和修改历史。
5. 忽略错误候选；被忽略内容不进入比较报告。

比较模块只使用已确认或高置信字段。多数据集、多指标和多结果在尚未建立实验归属时全部展示并阻止自动排名。

## 数据流与组件边界

1. v2 runner 负责新样本排除、证据冻结、单次调用和原始产物封存。
2. submission parser 负责协议诊断，不做语义修复。
3. scorer 负责绑定 occurrence、原始哈希、审核标签并计算指标。
4. confidence projector 依据结构、引文验证和确定性规则生成高置信／待核查视图，不修改原始记录。
5. FastAPI 返回候选证据及论文内检索请求所需身份。
6. Vue 页面展示候选、原文搜索结果和用户修订入口。

这些层之间只传递结构化对象。原始模型动作、自动卡、审核标签和用户 revision 分开保存，避免任何后处理覆盖原始输出。

## 产物

- `configs/evaluation/p46-quality-v2.json`：8 篇冻结新论文与模型预算。
- `data/processed/evaluation/p46-quality-v2/`：忽略的完整运行、trace、journal 和记录库。
- `docs/evaluation/p46-quality-v2/manifest.json`：可版本化身份与哈希。
- `docs/evaluation/p46-quality-v2/manual-review.json`：逐 occurrence 审核标签和身份状态。
- `docs/evaluation/p46-quality-v2/metrics.json`：四项主指标、覆盖率和混淆。
- `docs/evaluation/p46-quality-v2/report.md`：质量门结论和逐篇诊断。
- `docs/evaluation/p46-quality-v2/human-review.md`：供用户确认的原始字段和证据工作表。
- 若失败：候选置信视图、论文内证据搜索接口和网页核查流程。

## 验证范围

- 新样本与所有旧运行无交集；每篇恰好一次付费调用。
- manifest、journal、trace、结果、源码身份及审核字段哈希可相互验证。
- 四项指标可从封存产物离线重算。
- 多条目顺序和证据绑定在保存、加载、修订和报告中保持一致。
- 降级候选不能跨论文取证；用户确认生成追加 revision。
- 原 P4.6 v1 报告、测试集和保护文件保持不变。
- Python 全量测试、Ruff、前端生产构建以及关键网页交互通过。

## 完成判定

- 若四项阈值及审计完整性全部通过：P4.6 质量门标记为通过，降级交互可作为后续增强。
- 若任一阈值未通过：真实结果保持失败，随即实现并验收可核查降级流程；完成该流程后，P4.6 可标记为“有边界的产品可用”，不能标记为自动抽取质量通过。
