# P5 只读演示内容完善设计

## 背景与问题

当前 `frontend/src/demo/swin-case.json` 只有一条论文证据和两个提取字段（`model`、`result`）。页面按照九类字段固定渲染，因此任务、数据集、输入设置、训练、指标、限制和代码入口均显示“未提取”。页面行为正确，缺口来自演示 fixture 内容不足；这与《P5 演示与历史版本使用说明》中“展示筛选、提取、证据、历史差异和研究报告”的描述不一致，也无法在比赛录屏中体现论文、代码、配置和 Agent 的协同。

本设计扩充固定 Swin 案例，不改变在线检索、真实生成或 P6 冻结评测逻辑。所有新增内容仍明确标记为“预置演示数据 · 本地快照”，不得宣称为当前模型调用结果。

## 目标与验收标准

只读模式加载后，评委无需后端或 API，即可沿一篇固定版本的 Swin Transformer 论文完成以下查看路径：

1. 看到论文候选、版本和当前筛选决定。
2. 在实验信息卡中看到九个页面字段都有实质内容：任务、模型、数据集、输入设置、训练、指标、结果、限制、代码入口。
3. 点击每个字段的“查看证据”，能在右侧看到对应论文页码或官方仓库文件行号。
4. 看到至少两个提取版本，以及旧版到新版的新增、修改和冲突保留。
5. 阅读一份与信息卡一致的单篇研究报告。
6. 查看已有 Agent 多步检索、工具选择、引用回答和证据不足结论。

验收时不得出现“字段有值但证据数组为空”、跨论文取证、把 81.2 与 81.3 合并为唯一值、或把预置数据描述为实时生成。

## 内容方案

### 当前版本信息卡

当前版本围绕“如何从论文、配置和代码理解并复现 Swin-T”组织，使用固定论文 `arXiv:2103.14030v2 / ICCV 2021` 和官方仓库 commit `f82860bfb5225915aca09c3227159ee9e1df874d`。

| 字段 | 演示内容 | 主要证据 |
| --- | --- | --- |
| 任务 | 通用视觉骨干网络，覆盖图像分类、目标检测与语义分割 | 论文摘要／第 1 页 |
| 模型 | Swin Transformer Tiny；分层表示与 shifted-window self-attention | 论文第 2–5 页 |
| 数据集 | ImageNet-1K；COCO；ADE20K，按条目分别展示 | 论文实验部分对应表格与正文 |
| 输入设置 | 224×224 输入、4×4 patch、7×7 window | 论文 Section 3.3；固定 Swin-T YAML |
| 训练 | ImageNet-1K 的训练设置及官方配置默认值，明确区分论文设置和代码默认值 | 论文 Appendix A2.1；`config.py` |
| 指标 | ImageNet-1K top-1 accuracy | 论文 Table 1(a)；仓库 README 模型表 |
| 结果 | 论文报告 81.3%，仓库固定 checkpoint 表报告 81.2%，作为两条冲突来源保留 | 论文第 6 页；README 110–118 行 |
| 限制 | 固定实现的 `PatchEmbed.forward` 对输入高宽执行显式尺寸断言；改变输入分辨率需同步处理配置与权重 | `models/swin_transformer.py` 448–475 行；官方高分辨率微调说明 |
| 代码入口 | 官方 Swin-T YAML、模型构建入口和 `SwinTransformer` 实现位置 | YAML 1–9 行；`models/build.py` 34–52 行；模型源码 448–565 行 |

字段值采用中文总结，但 `verbatim` Claim 的 `quote` 必须是固定来源中的连续原文。推断性总结使用 `requires_review`，不得伪装成原文字面结论。论文与仓库数值冲突分别保留来源和适用口径。

### 证据集合

fixture 的 `candidate.evidence` 从一条扩展为覆盖上述字段的有界证据集合。每项保留：

- 稳定的 `chunk_id`；
- 论文或官方仓库 `source_id`；
- `source_type`、路径和固定版本；
- 论文页码或代码／配置行号；
- 可直接展示的原文片段。

优先复用当前 v2 Swin collection 已存在的真实 chunk。若一个现有 chunk 太大，只在 fixture 展示时截取连续片段，不修改索引或原始数据。历史记录中的每个 evidence ID 都必须能在 `candidate.evidence` 找到，页面现有 `enrichEvidence` 才能填充可点击证据对象。

### 历史版本与差异

保留两版筛选记录和两版提取记录：

- 初始版：只包含任务、模型、核心 shifted-window 结果和一条待核对的性能记录，体现自动整理后的不完整状态。
- 修订版：补充数据集、输入、训练、指标、限制和代码入口；将 81.2／81.3 拆成独立结果并标记来源冲突。

这样历史差异表会同时出现新增字段、修改字段和同名多结果，展示人工修订与证据追溯价值。版本 UUID、`revision_of` 和 `card_id` 保持合法且稳定，刷新页面不会改变。

### 报告与 Agent 回放

单篇报告与修订版信息卡使用同一组事实，按“研究范围—架构与输入—训练和数据—指标与结果—论文／仓库冲突—复现限制—证据来源”组织。报告不进行跨模型性能排名。

现有 Agent 回放继续使用已封存的真实开发任务，展示三轮检索、工具选择、最终引用回答，以及“当前证据无法说明作者明确动机”的证据不足判断。该问题与信息卡互补：信息卡展示结构化科研材料，Agent 展示受约束的多步核查。

## 数据流与组件边界

`loadDemoCase()` 仍是唯一入口：导入固定 fixture，填充候选论文、当前卡、历史记录、报告和证据面板；`swin-agent-trace.json` 独立提供 Agent 回放。演示数据不请求 `/v1`、不写本地存储、不修改真实研究记录。

不把大量内容硬编码进 `App.vue`。Swin 内容保留在 JSON fixture；新增一个小型 fixture 合同校验模块，仅负责检查字段覆盖、证据引用完整性、版本关系和只读标识。页面组件继续消费现有 `CardResponse`／`ResearchHistory` 类型。

## 失败处理

- fixture 缺少必需字段或引用不存在的 evidence ID 时，构建测试直接失败，不发布空壳演示。
- 某条证据没有可识别位置时，页面显示现有路径与版本说明，不生成虚假页码或行号。
- 公网只读构建继续隐藏退出与在线操作；本地完整模式仍可退出演示恢复原状态。
- 演示内容与真实 API 数据完全隔离，刷新只会恢复固定快照。

## 测试与验收

1. 新增 fixture 合同测试，断言修订版覆盖九类字段、各字段至少一个 Claim、每个 evidence ID 都可解析、两版 revision 链有效。
2. 断言论文 81.3 与仓库 81.2 为两条独立结果，且证据来源不同。
3. 运行前端 Vitest、TypeScript 检查和 Vite 默认构建。
4. 使用 `VITE_DEMO_ONLY=true` 运行静态构建，确认无 `/v1` 请求。
5. 浏览器逐项检查：信息卡不再出现“未提取”；字段证据可打开；历史差异、报告和 Agent 回放均有内容；退出演示后本地在线状态仍可恢复。

## 范围边界

本节点只完善固定 Swin 只读演示内容和合同测试。不新增第二篇论文的离线比较、不改在线自动抽取提示、不重新运行 P6、不用冻结测试答案填充 fixture，也不改变 Cloudflare Pages 的只读部署方式。
