# ICAN 赛事演示讲解稿

- **目标时长：** 4 分 50 秒（赛事上限 5 分钟）
- **屏幕：** 16:9 桌面浏览器；Swin 只读回放
- **配套操作：** [赛事演示操作手册](contest-demo-operation-manual.md)

> 录制口径：筛选、信息卡、历史和报告是预置的同论文演示数据；Agent 轨迹来自该论文的一次真实、已完成的 P4 开发运行，不是录制时重新发起的在线任务。讲解时保留这个区别。

| 时间 | 屏幕操作 | 讲解词 |
|---|---|---|
| 00:00–00:30 | 停在演示中心标题区；点击“载入 Swin 只读回放”，让模式标签保持可见。 | 大家好，这是“复现有据”ICAN。研究者复现视觉模型时，常常要在论文、代码和配置之间来回确认：结论来自哪里，代码是否真的这样实现，证据有没有覆盖到问题。这个网页把这些核对步骤放在同一个工作区里。现在载入的是 Swin 的只读演示案例。 |
| 00:30–01:05 | 点击导航里的“论文筛选”，停在候选论文、查询内容和证据摘要。 | 我们从一个具体问题开始：论文和官方实现能否说明，Patch Embedding 卷积投影之后为什么默认接 LayerNorm？系统的检索范围限定在已整理的论文与代码语料，候选结果会保留来源和版本，方便研究者先判断这篇论文是否适合继续核查。 |
| 01:05–01:45 | 跳到“信息卡与历史”；展示字段、筛选记录、两版选择器和差异表。 | 对选中的论文，工作台把实验和实现信息整理为字段，并把筛选决定、字段版本和证据位置留在记录里。这里展示的是预置样例：可以比较两个版本，查看字段如何变化，以及每条研究陈述对应的原文或待复核状态。这样修改记录仍然可追溯，也不会覆盖旧版本。 |
| 01:45–03:10 | 跳到“Agent 工具”；依次指向问题、状态、用量、planning 与 search_evidence、gen_answer 事件，再停在回答。 | 接下来是 Agent。这个面板展示的是此前真实完成的一次开发运行回放，不是此刻刚提交的在线请求。任务接收到刚才的问题后，规划器多轮选择证据检索工具，再把保留的证据交给回答模块。页面按真实发生顺序列出规划事件、检索范围、工具状态和最终回答；这次记录显示四次付费模型调用，使用的规划模型和回答模型也如实列出。费用没有从服务返回，所以界面不会猜一个数。 |
| 03:10–04:20 | 点击回答中的论文引用，展示右侧原文证据；再点代码引用，展示仓库路径、版本和代码行。 | 现在沿着引用回到来源。论文证据介绍了 Patch Embedding 的分块和投影过程；官方代码与配置显示，PatchEmbed 在卷积投影后执行归一化，而且默认配置开启了这项处理。请注意，这些材料能证明实现做了什么，却没有说明作者为什么作出这个设计选择。因此系统的回答是：现有证据无法确认明确动机。它把证据边界留在结果里，而不是补写一个听起来合理的解释。 |
| 04:20–04:50 | 保持证据面板和结论同屏，或回到演示中心总览。 | 这就是 ICAN 的核心流程：从研究问题出发，连接论文筛选、结构化记录、Agent 工具和原文证据。它帮助研究者更方便地复核材料；自动提取结果仍需要人工检查。我们希望让每个结论都能回到来源，也让证据不足清楚可见。谢谢。 |

## 录制前核对

- 页面模式显示“预置运行回放 · 只读”。
- 预置轨迹中的模型调用量与页面显示一致；实际费用显示“未提供”。
- 第一处引用定位到论文第 3 页；代码引用显示固定仓库版本与对应行号。
- 计时目标为 4:50；如果现场翻页或朗读较慢，优先缩短开场和字段说明，保留 Agent、证据回查和边界说明。
- 如改为现场在线执行，应将“运行回放”改为“在线执行结果”，明确等待服务端返回；在线运行耗时不确定，需预先测试并获得模型调用预算。不要把预置筛选／信息卡说成这次在线任务新生成的产物。

## 面向评分点的讲解落点

- **创新性：** 论文、代码、配置之间的可追溯核对。
- **技术实现：** RAG 证据检索、Agent 工具链、历史记录与引用定位。
- **实用价值：** 降低查找和复核分散材料的操作负担；当前不宣称量化效率提升。
- **用户体验：** 五阶段导航、版本对比、一键只读演示和证据回查。
- **展示效果：** 用一个具体问题串起全过程，并以“证据不足”展示系统边界。
