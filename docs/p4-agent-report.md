## 真实案例：执行完成不等于答案正确

下表是选定开发案例的助手逐条核查，不是全开发集／外部评测，也不是人工审核。v2和v5源码不同，不拼成同版本准确率。原始回答、任务／源码／journal SHA及引用位置见[验收摘要](evaluation/p4-agent-summary.json)。引用身份均与原始chunk正文及来源核对一致。

| 案例／版本 | 实际请求数 | 实际结果与核查 |
|---|---:|---|
| 学习率／v2 | 3 Pro＋1 Flash | 正确得到0.002，同时引用默认5e-4和main.py缩放公式。回答未单列中间0.001，不判全部rubric覆盖 |
| DROP_PATH_RATE／v2 | 2 Pro＋1 Flash | 静态默认0.1→具名YAML0.2正确；两项直接引用成立。最终选块未包含merge实现，覆盖顺序的原文引用仍应补全 |
| LayerNorm动机／v2 | 3 Pro＋1 Flash | 实现事实引用正确SWIN分支，明确作者动机证据不足；现有语言识别规则却返回completed／answered，状态漏识别保留 |
| 112输入尺寸／v5 | 4 Pro＋1 Flash | 已生成但**答案错误**。回答称第四stage窗口失败；实际第三次PatchMerging面对7×7时已被偶数断言阻止 |

shape回答将`7//2=3`当作实际执行后的尺寸，还声称存在未引用的窗口整除断言。原证据`PatchMerging.forward`第331–352行已经包含`assert H % 2 == 0 and W % 2 == 0`。算术工具正确计算不代表代码满足前置条件，引用ID存在也不能证明答句受支持。该案例没有通过语义验收，不宣称P3跨stage错误已解决。

## 失败、调度修复及保留记录

共保留9个真实任务：6个执行到生成，3个因5轮规划耗尽停止。6个生成并不等于6个正确答案。

- 首轮学习率结果正确但默认值引用不足；后续v2同时取得默认值和公式依据。原轮保留。
- shape v2：计算器不支持`//`，按预算停止。扩展整数整除／取模，保持有界AST及Python负数语义。
- shape v3：模型向单标量工具传tuple；v4忽略最后一轮提示，继续计算。两轮仍按budget_exhausted停止，没有自动追加回答。
- 调整为已有证据时最后一次预算内规划只开放gen_answer。模型仍选择原文ID；非法额外调查不执行，没有证据时不强制回答。v5在第4轮主动调用gen_answer，**未触发强制收尾阶段**，因此本次真实结果不能证明最后一轮调度修复有效；该边界由原生fake工作流覆盖。
- 独立审查发现超时被上游吞成普通错误、畸形工具结构、模型猜覆盖参数冒称用户等重要问题，均修复。最终整除及收尾变更由本地自查与回归验证；后续独立复查未完成，审查器触及使用额度。
