# ICAN 真实后端赛事演示视频文字稿

- **作品名称：** 复现有据 · ICAN
- **成片目标：** 4 分 45 秒，严格不超过 5 分钟
- **录制方式：** 一份全程连续母版；成片只压缩两段模型等待
- **演示模式：** FastAPI 真实后端、真实检索、真实信息卡生成、真实 Agent 核查
- **备用材料：** [只读回放讲解稿](contest-demo-script.md)

> 本稿用于正式参赛视频。录制时不得进入“载入 Swin 只读回放”，也不得把历史结果冒充本次在线生成。页面实际返回的状态、模型、调用量、token、停止原因和引用优先于预写讲解词。

## 一、正式录制使用的两个问题

### 1. 论文检索与实验信息卡

选择语料：

```text
Swin Transformer
```

检索问题：

```text
梳理 Swin Transformer 的层级架构、Patch Merging、训练数据集、评价指标和主要实验结果，并保留论文原文证据。
```

在线操作：检索论文 → 选择 Swin Transformer 原论文 → 从原文生成。

### 2. Agent 复现核查

核查类型：

```text
代码前置条件
```

Agent 问题：

```text
在固定官方 Swin-T 的 PatchMerging.forward 中，给定 H=8、W=8、L=64，长度和奇偶性前置条件是否通过？四路切片拼接后通道维度如何变化？请引用官方源码说明，不能把静态核查说成实际训练运行。
```

这不是冻结测试题。它用于产品演示，目标是展示 Agent 如何在限定语料和工具范围内核查源码条件。

## 二、录制前准备

### 2.1 服务检查

在服务器电脑确认 ICAN 服务正在运行。若使用本机录制：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

若使用 Cloudflare Tunnel 录制：

```powershell
Invoke-RestMethod https://ican.你的域名/health
```

健康接口必须返回：

```json
{"status":"ok"}
```

检查完成后关闭终端，正式录屏不展示 `.env`、API Key、Cloudflare Tunnel Token 或命令历史。

### 2.2 页面准备

1. 使用 1920×1080、16:9 录制，浏览器缩放建议为 90% 或 100%。
2. 关闭书签栏、下载栏、聊天窗口、系统通知和密码管理器弹窗。
3. 打开 ICAN 首页，确认没有进入只读回放；如果页面显示“退出演示”，先退出演示再刷新。
4. 将论文筛选、实验信息卡、记录历史、复现核查和证据面板全部展开。
5. 将两个正式问题预先保存在本地纯文本中，录制时复制粘贴，避免现场输入错误。
6. 确认 Swin collection、索引、论文原文、官方仓库证据和模型服务均可用。
7. 正式录制前只做健康检查与只读检索检查，不预跑本次信息卡和 Agent 问题来挑选结果。

### 2.3 录音准备

- 语速保持每分钟约 230–260 个汉字。
- 点击按钮后先停半秒，让观众看清操作，再继续讲解。
- 模型等待期间停止长篇讲解，给后期留下明确剪辑点。
- 讲解中不朗读完整 chunk ID、record ID 或 token 数字；让画面承担这些细节。

## 三、连续母版操作顺序

录制开始后不中断屏幕录制，按以下顺序操作：

1. 停在页面标题与论文检索区域，开始开场讲解。
2. 选择 Swin Transformer collection，粘贴论文检索问题。
3. 点击“检索论文”，等待真实后端返回候选。
4. 指向候选论文的标题、来源版本与证据摘要。
5. 勾选 Swin Transformer 原论文，点击“从原文生成”。
6. 保留“请求已提交／生成中”的真实画面；等待期间不停止母版录制。
7. 返回后依次展示阶段状态、模型调用量、筛选决定和实验信息字段。
8. 在数据集、指标或结果中选择一条本次实际生成且带证据的字段，点击“查看证据”。
9. 展示论文页码／段落、来源版本与原文摘录，再关闭证据面板。
10. 滚动到“记录历史”，展示新记录及已有版本；如果当前只有一版，只展示追加式记录，不强行比较。
11. 滚动到“复现核查”，粘贴 Agent 问题，选择“代码前置条件”。
12. 点击“运行核查”，保留“请求已提交”的真实画面；等待期间不中断母版。
13. 返回后展示任务状态、规划模型、回答模型、调用量、停止原因和工具轨迹。
14. 按实际顺序指向检索、原块读取、条件核查、结论提交和回答事件；没有出现的事件不得口头补造。
15. 展示最终回答与 Claim 状态，点击一条官方源码引用。
16. 在证据面板展示固定仓库版本、文件路径、代码行和原文。
17. 将答案与源码证据保持同屏，完成结尾讲解后停止录制。

## 五、等待画面的剪辑方法

每次在线任务使用相同结构：

1. 保留点击按钮前 1 秒。
2. 保留点击、按钮进入加载态以及“请求已提交”画面至少 2 秒。
3. 删除中间无交互等待，但连续母版中必须保留。
4. 插入纯文字转场：

   ```text
   真实在线执行
   等待过程已压缩
   ```

5. 保留返回结果首次出现后的 2 秒，再继续鼠标操作。
6. 不使用“模型正在思考”之类无法由产品状态证明的字幕。
7. 不填写虚构的节省时长或加速倍数；需要标时可使用母版的真实起止时间。

## 六、现场结果分支话术

正式讲解前先看清页面状态，再选择对应话术。以下句子可以替换第四节中的结果说明。

### 6.1 信息卡完整生成

> 这次任务完成了证据准备、模型提交、结果校验和记录保存。页面展示本次真实用量，并将通过校验的字段写入可追溯研究记录。接下来我选择一条字段回到论文原文核查。

### 6.2 信息卡需要人工复核

> 这次模型已经返回候选内容，但确定性检查没有把所有字段直接当成可靠结果。页面把存在归类、引文或缺项疑问的内容交给人工确认，研究者可以限定在当前论文内继续搜索、修改字段并保存新版本。

### 6.3 信息卡输出达到长度上限

> 页面明确记录模型输出达到长度上限，因此没有把不完整结构保存成研究卡。系统区分输出截断与服务不可用，也不会自动再次产生付费调用。为了保持本次运行真实，这段结果按失败终态保留。

### 6.4 Agent 完成且引用支持结论

> 本次 Agent 在限定预算内完成工具选择和结论提交。这里展示的是实际工具顺序和最终引用；我继续打开官方源码，核对回答中的条件和通道变化。

### 6.5 Agent 返回需要复核

> Agent 已经形成有引用的候选结论，但其中包含需要研究者判断的推断。系统保留“需要复核”状态，没有把模型判断包装成确定事实。现在我沿引用检查它使用的源码范围。

### 6.6 Agent 返回前置条件阻断

> 静态核查发现输入没有满足源码前置条件，因此工作流在这里阻断后续结论。这个终态说明系统不会在条件不成立时继续假设代码已经成功执行。

### 6.7 Agent 返回证据不足

> 当前限定语料不足以支持完整结论，Agent 将任务标记为证据不足。它保留已经找到的来源，同时拒绝用常识补齐缺失部分，这也是可信科研助手必须具备的边界。

### 6.8 网络或模型请求失败

> 这次在线任务没有完成，页面保留了失败阶段和停止原因，也没有自动重试付费模型。连续母版将保存这次失败；如果重新录制，会从新的完整请求开始，不把不同任务剪成一次结果。

## 七、录制画面检查清单

### 7.1 必须出现

- [ ] 网页标题“复现有据 · ICAN”。
- [ ] 在线论文检索问题和 Swin collection。
- [ ] “检索论文”真实点击及后端返回的候选。
- [ ] “从原文生成”真实点击及生成状态。
- [ ] 信息卡的真实调用量、阶段与停止原因。
- [ ] 至少一个本次信息卡字段及其论文原文证据。
- [ ] 记录历史或追加式版本入口。
- [ ] Agent 完整问题和“代码前置条件”类型。
- [ ] “运行核查”真实点击及提交状态。
- [ ] Agent 的任务状态、模型、调用量、停止原因和实际工具轨迹。
- [ ] 最终回答或真实失败终态。
- [ ] 至少一条官方源码引用，包括仓库版本、路径和代码行。
- [ ] 两处“真实在线执行 · 等待过程已压缩”字幕。

### 7.2 不得出现

- [ ] `.env` 文件内容。
- [ ] DeepSeek API Key。
- [ ] Cloudflare Tunnel Token。
- [ ] 浏览器保存的账号密码、邮箱通知或私人书签。
- [ ] 冻结测试答案、评测标注或内部审核文件。
- [ ] 将只读 fixture、旧任务或历史卡描述为本次在线生成。
- [ ] 将“原文匹配”描述为语义百分之百正确。
- [ ] 将静态条件核查描述为运行完整训练代码。
- [ ] 将模型工具调用过程描述为公开内部思维链。

## 八、成片验收清单

- [ ] MP4 文件可正常播放，画面为 16:9，文字可读。

- [ ] 两次在线提交、两次返回以及剪辑转场逻辑连续。
- [ ] 没有把不同 task、不同信息卡运行或不同日期结果拼接成同一次任务。
- [ ] 页面实际状态与讲解词一致。
- [ ] 论文证据和源码证据都能看清来源位置。
- [ ] Agent 轨迹体现接收请求、选择工具、获得结果、形成反馈。
- [ ] 结尾明确 AI、确定性程序和人工复核的分工。
